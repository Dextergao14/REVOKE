## Abstract

As LLM agents are deployed over ever longer horizons, their memory systems have split into two families: *declarative memory middleware* that records facts about users and the world, and *self-evolving experiential memory* that distils insights, workflows and skills from the agent's own trajectories. Existing benchmarks probe only the former's recall fidelity; the recent turn to *state tracking* keeps evaluation at the answer level and does not touch the second family at all. We present **REVOKE**, a benchmark in which agents perform open-ended tool-use tasks in programmatically verifiable environments whose constraints evolve over time through six event types — addition, supersession, conditionalisation, conflict, support and partial retraction. Grading is deliberately asymmetric: any action in the trace that contradicts the current constraint closure fails the episode; all other behaviour is unconstrained. Ground truth is a two-layer graph construction — a persistent base of defeasible rules with priorities, and a per-step derivation layer that computes the grounded extension of a defeat graph followed by a stratified Datalog closure — which makes grading unique, polynomial-time and independent of deletion order. Scenarios are not hand-written: constraint evolution is generated by traversing a DAG of reusable *event-subgraph motifs*, and every generated timeline is accepted only after passing seven solver-side checks, including a guarantee that every priority resolution is recoverable from the transcript alone. REVOKE contains XX episodes, XX graded decision points and XX *stale-memory traps* — points at which an option that was compliant earlier in the episode has become a violation. We evaluate XX systems from both memory families under a single behavioural criterion and report per-event-type violation rates, adaptation lag, update interference and staleness attribution, all computed on the graph without an LLM judge. Preliminary results indicate that XX.

## 1 Introduction

Agent memory research advances along two largely disjoint tracks. The first treats memory as a declarative store: extract profiles, preferences and events from conversation, write them to external storage, retrieve on demand. It is evaluated by long-horizon question answering — *did the system remember correctly?* The second treats memory as procedural experience: distilled insights, induced workflows, synthesised skills, and increasingly the memory architecture itself evolving under a task-success signal. It is evaluated by task success on agentic suites — *did the agent get better at doing?* Both sidestep the same question: **when the rules of the world change, does what memory holds remain valid?**

For declarative memory this question has only just been raised, and only at the answer level: facts and decisions are revised across sessions, and a QA response must reflect the current state rather than a superseded one. But real agent failures happen at the level of behaviour — booking a vendor that has since been banned, calling an API that has been deprecated, administering a drug for which a contraindication has since been recorded. A correct answer does not imply compliant behaviour, and conversely, behavioural grading naturally accommodates open-ended, multi-solution execution with no fixed answer space.

For experiential memory the question has never been examined. Every distilled insight and consolidated workflow was validated under some particular world state. When constraints evolve, that experience does not expire on its own: it keeps being retrieved and reused, and because it remains effective on the old distribution it can even survive selection in success-driven evolution. We name this failure mode **procedural memory invalidation**: learned experience degenerates into stale rules that induce violations. A system that only accumulates and never invalidates should exhibit the counter-intuitive pattern *more experience, more violations*.

REVOKE is built to quantify exactly that. Its design rests on four decisions.

1. **Behaviour, not answers.** An episode is graded on the actions in its trace, against a constraint closure that is recomputed at every step. One contradicting action fails the episode regardless of anything else; detours, exploration and sub-optimal solutions are never penalised. This isolates memory consistency from policy optimality.
2. **A formal, unique ground truth.** Constraints are defeasible rules with explicit priorities in a decidable fragment. The current closure is the stratified Datalog consequence of the grounded extension of a defeat graph — unique, polynomial-time, deletion-order independent — so every action has a single, machine-checkable verdict.
3. **Generation as graph traversal.** Constraint evolution is composed from a library of domain-agnostic *motifs*, each a small event subgraph with a designed invalidation. Motifs form a DAG whose linear extensions are the admissible timelines; a randomised traversal produces scenarios at scale, and ground truth is always re-derived by the solver rather than trusted from the motif's design intent.
4. **Two grading gates.** Permissive-default violation grading is exploitable by an agent that never acts, or that always acts on something no rule mentions. An episode therefore scores only if it is violation-free *and* every task is completed on an option the closure positively licenses.

**Contributions.**
- We formalise procedural memory invalidation and move evolving-state evaluation from the answer level to the behaviour level (trace violation grading).
- We build REVOKE on a two-layer argumentation-style construction — grounded extension over a defeat graph plus stratified Datalog closure — with six state-evolution event types, open-ended tasks and programmatic checkers, and no LLM judge.
- We introduce a motif library and a DAG-traversal generator that produce verified scenarios at scale, together with seven solver-side acceptance checks, one of which guarantees that every priority resolution the agent is graded on is recoverable from the transcript.
- We provide the first head-to-head comparison of declarative memory middleware and self-evolving experiential memory systems under one behavioural criterion, with metrics beyond pass/fail: per-event-type violation rate, adaptation lag, update interference and staleness attribution.

## 2 Related Work

**Declarative memory middleware.** Systems that extract, store and retrieve facts about the user and the world (mem0, MemOS, Zep, and related), evaluated on long-horizon conversational QA in the style of LoCoMo and LongMemEval. These benchmarks measure recall fidelity under a static world.

**Self-evolving experiential memory.** ExpeL distils cross-task insights; Agent Workflow Memory induces reusable workflows; Voyager and SkillWeaver synthesise skills and tools; Dynamic Cheatsheet maintains a self-curated note; MemEvolve lets the memory architecture itself evolve; EvolveLab unifies twelve such systems. All are evaluated by task success on GAIA- and WebArena-style suites. None is evaluated on whether its experience remains *valid* after the world changes.

**State tracking.** StateMemBench defines state tracking across sessions: facts and decisions are revised and answers must reflect the current state. It is QA-shaped, grades at the answer level against a closed pool, and covers supersession only. REVOKE covers supersession plus five further event types and grades behaviour.

**Defeasible reasoning and argumentation.** Our derivation layer is the grounded semantics of Dung's abstract argumentation frameworks, applied to instance-level defeat graphs built from priority-ordered defeasible rules, followed by stratified Datalog evaluation. Per-step whole-set recomputation sidesteps the over-deletion problem that Delete-and-Rederive addresses in incremental materialised-view maintenance; incremental maintenance is left as an optimisation.

**Agentic benchmarks with trace-level grading.** Source-grounded retrieval benchmarks have shown that raw accuracy can overstate capability by an order of magnitude once behavioural traces are inspected, and that leakage decomposes into scaffold-dependent modes. REVOKE inherits that methodology — grade the trace, not the answer; hand the agent a blind view; make the sandbox unable to leak — and applies it to memory rather than retrieval.

## 3 Problem Formulation

### 3.1 Procedural memory invalidation

Let $W_t$ be the world's constraint state at time $t$, and let $M$ be an agent's memory, each entry $m \in M$ having been validated under some state $W_{\tau(m)}$ with $\tau(m) \le t$. Entry $m$ is *stale* at $t$ if the behaviour it licenses is a violation under $W_t$. Procedural memory invalidation is the failure to retire stale entries: the agent retrieves $m$, acts on it, and violates. The phenomenon is only observable behaviourally, since $m$ may be perfectly *accurate* as a record of $W_{\tau(m)}$.

### 3.2 A two-layer graph construction

We represent constraint state as a graph, but split the intuitive picture — rules as nodes, relations as edges, contradiction as deletion — into two layers. Deletion happens only in a derivation layer that is recomputed at every timestep; the persistent layer never loses information on conflict.

**Persistent layer.** $R_t = \{(r_i, \pi_i)\}$: defeasible rules $h \Leftarrow b_1 \wedge \dots \wedge b_k$ with integer priorities. Heads carry classical negation; bodies are positive. Six events drive evolution:

| event | operation on $R_t$ | destructive? |
|---|---|---|
| ADD | insert a rule | no |
| SUPERSEDE | replace a rule's head/body | yes |
| CONDITION | rewrite a rule's body (unconditional ↔ conditional) | no |
| CONFLICT | insert a rule with a contradictory head; resolved by priority | no |
| SUPPORT | insert nothing; raise the priority of an existing rule | no |
| RETRACT | withdraw a subset of a rule's ground instances | yes |

Support is folded into priorities, avoiding bipolar argumentation frameworks. Except for SUPERSEDE and RETRACT the persistent layer is append-only, which is what makes staleness attribution (§5.3) well defined.

**Derivation layer.** Recomputed at each $t$, never stored:

1. *Grounding.* Instantiate every live rule over a sorted Herbrand universe. Nodes are ground rule **instances**, not rules. This is what covers CONDITION, CONFLICT and RETRACT: a rule defeated in one instantiation stays valid in another.
2. *Defeat graph.* Edge $n \to m$ whenever the heads of $n$ and $m$ are complementary and $\pi(n) > \pi(m)$.
3. *Grounded extension.* Iterated deletion to fixpoint: a node is IN once all its attackers are OUT, OUT once any attacker is IN. Survivors form $E_t$; the deleted set is $D_t$.
4. *Stratified closure.* Forward-chain over $E_t$ to obtain $C_t$.

Because step 4 recomputes over the entire surviving set, any conclusion with an alternative derivation is automatically re-derived — the over-deletion pitfall of "delete the node and its outgoing edges" over the old closure is avoided.

**Properties.** (i) Priorities are strict, so the attack relation is acyclic and $E_t$ is unique and polynomial-time computable. (ii) Removing nodes or edges cannot create negative cycles, so every subgraph remains stratifiable — the semantics is well defined throughout evolution. This is well-definedness, not conclusion preservation: negation makes the logic non-monotone and deletion can flip conclusions, which is exactly the phenomenon under test. (iii) The implementation is an executable specification: the two worked examples of Appendix A are pinned as tests.

### 3.3 Grading

Every tool call maps to a set of asserted ground literals. Action $a_i$ at time $t$ is a **violation** iff $C_t \cup \mathrm{assert}(a_i)$ derives a contradiction, where the asserted literals are pushed through the surviving instances $E_t$ — so a violation may surface several derivation steps away from the action. Read-only tools assert nothing and are never graded.

The default is permissive: if $C_t$ says nothing about an entity, acting on it is not a violation. On its own this is exploitable twice — *never act*, or *always act on something no rule mentions*. REVOKE therefore grades two gates:

- **Violation gate.** Any violating action fails the episode. Asymmetric and absolute.
- **Completion gate.** Each task must be completed by acting on an option that $C_t$ *positively licenses* ($\mathrm{allow}(e) \in C_t$). An unmentioned entity is safe but does not complete the task.

An episode scores 1 iff it passes both. The two gates are reported separately as well (§5.3), because they fail for opposite reasons.

## 4 Benchmark Construction

### 4.1 Motifs: reusable event subgraphs

A **motif** is a domain-agnostic template over a permission predicate $\mathrm{allow}/1$ on the domain's primary sort, a set of 0-ary context predicates, and a group predicate $\mathrm{grp}/2$. It emits an ordered chain of **beats**; each beat is one atomic step of evolution — a small set of events applied together — optionally followed by a **probe**, a task the agent must execute immediately, restricted to an explicit option set. Motifs are designed so that the option set at consecutive probes stays constant while its *compliant subset* changes. An agent replaying experience from an earlier probe therefore violates.

| motif | events | designed invalidation |
|---|---|---|
| `conflict_flip` | ADD → CONFLICT → SUPPORT (+CONFLICT) | banned entity reinstated by priority while its alternative is withdrawn |
| `supersede_alt` | ADD ×2 → SUPERSEDE | consolidated path retired; task survives through a second derivation |
| `conditionalize` | ADD → CONFLICT → CONDITION → context | blanket ban narrowed to a condition, then re-triggered |
| `retract_partial` | ADD → group CONFLICT → RETRACT (+CONFLICT) | a member leaves the blanket ban as the old carve-out closes |
| `conflict_chain` | ADD → CONFLICT → CONFLICT (override) | middle rule's verdict overturned by a higher one |
| `support_threshold` | ADD + advisory CONFLICT → SUPPORT | an explicitly advisory objection is escalated past the permission |
| `condition_widen` | ADD + conditional CONFLICT → CONDITION | the qualifier the agent relied on disappears |
| `canary` | ADD only | nothing applies; calibrates false positives |

### 4.2 Generation as DAG traversal

Chains are internally ordered and mutually independent, so the beats of the XX–XX motifs in a scenario form a DAG whose linear extensions are the admissible timelines. The generator performs a randomised topological linearisation, choosing the next chain with probability proportional to its remaining length so that long motifs do not clump. Beats are laid onto a session grid with gaps drawn from the density regime; each probe is placed strictly inside its beat's window; **echo probes** repeat the same option set at the following one or two sessions so that adaptation lag is observable; filler turns occupy empty sessions.

Every probe's option set is then widened with one or two **distractors** — entities from other motifs the transcript has already named, or entities no rule ever mentions — and shuffled. Positional priors carry no signal, and the "unmentioned" distractors are exactly the safe-but-unlicensed options that make the completion gate necessary.

**Ground truth is never taken from the motif's design intent.** After the timeline exists, every probe is re-scored against the closure the solver actually produces at that session: the compliant set, the licensed set, the violating set with the rules to blame, the deleted set $D_t$, whether the compliant set changed since the previous probe on the same options (*flip*), and which options were compliant then but violate now (*stale trap*).

### 4.3 Acceptance checks

A scenario is emitted only if it passes all of the following; failures are rejected, never repaired.

1. The closure converges and is consistent at every session $0..T$.
2. No probe is must-violate: every probe has at least one compliant option.
3. Every probe has at least one *licensed* option, so the task is completable.
4. Over-deletion guard: the feasibility predicate $\mathrm{feasible} \Leftarrow \mathrm{allow}(X)$ is in $C_t$ iff some positive permission survives — i.e. it is re-derived through a surviving path whenever one exists.
5. At least one stale trap exists; every probe is rendered into the transcript.
6. Self-containedness: every violating option was named in a turn before the probe that offers it. (Compliant options may be unmentioned — that is the permissive default under test.)
7. **Priority recoverability.** For every defeat edge active at a probe, the winning rule is either the more recently stated one, or was written by an event carrying explicit override language, or the losing rule was stated as explicitly advisory. The agent is never graded on a resolution it had no way of reading.

Check 7 caught two generator bugs during development — a SUPPORT whose prose was about the wrong entity, and a blanket ban over a reused group that reached into another motif's entities — both of which produced *correct* closures that were nevertheless unfair to the agent.

### 4.4 Domains

Five seed domains supply vocabulary, entities and prose but **no logic**; every domain is graded by the same engine.

| domain | primary sort | act tool | example contexts |
|---|---|---|---|
| Platform API governance | endpoint | `call_endpoint` | change freeze, incident open, peak hours |
| Procurement compliance | vendor | `place_order` | low-budget quarter, audit open, fiscal close |
| Clinical medication constraints (fully synthetic formulary) | drug | `administer` | renal impairment, on anticoagulant, febrile |
| Household automation preferences | routine | `run_routine` | baby asleep, guest present, away mode |
| Financial operation permissions | operation | `execute_operation` | above limit, sanctions review, market halt |

Each domain also exposes read-only tools (`read_*`, `list_*`). The mock sandbox returns nothing substantive about policy from them by design: the constraint history exists only in the conversation, which is what makes REVOKE a memory benchmark rather than a retrieval one.

Priority is realised in prose by three devices, and only these: *recency* (a later rule addressing the same entity supersedes), *explicit override language* for SUPPORT and top-of-chain CONFLICT, and *explicit advisory language* for a CONFLICT that is meant to lose. Check 7 enforces that no other device is ever needed.

### 4.6 Anti-leakage protocol

Agents receive only a *blind* view: transcript, tool surface and option sets. Rule vocabulary, universe, events, closure and labels are stripped. The runner refuses to start on a file that carries ground truth. The grader rebuilds ground truth from the item's event log with the same engine that generated it and never trusts cached labels.

## 5 Evaluation Protocol

### 5.1 Systems under test

Three baseline groups: **long-context** (full transcript in context); **retrieval** (RAG over prior sessions); and **memory systems** — declarative middleware (mem0, MemOS, Zep, OmniMemory) and self-evolving systems (the twelve unified in EvolveLab, including ExpeL, AWM, Dynamic Cheatsheet and Voyager-style skill libraries). Each is run on XX backbones. The shipped runner implements three memory conditions directly — `full`, `window` (last $K$ sessions), and `notes` (last $K$ sessions plus a self-maintained scratchpad exposed as a `remember` tool) — as the cheapest stand-ins for the three groups.

### 5.2 Scripted reference policies

Six policies without a model, to fix the scale and to validate the grader: **oracle** (always a licensed option); **stale** (solves each option set correctly the first time, then replays the consolidated choice — procedural memory invalidation in its purest form); **first** (the option named earliest in the transcript); **recency** (the option named in the most recent update); **refuse** (never acts); **random**.

### 5.3 Metrics

| metric | definition |
|---|---|
| **CSR** compliant success rate | episodes that are violation-free *and* completed every probe — the headline |
| **VFR** violation-free rate | episodes with no violating action; reported alongside CSR, never alone, since inaction achieves it trivially |
| **Violation rate** | probe-level, decomposed by the six event types |
| **Stale-trap rate** | share of stale traps where the agent replayed the now-invalid choice |
| **Adaptation lag** | probes after a flip until the agent stops violating on that option set; right-censored cases reported separately |
| **Update interference** | violation-rate difference on *unchanged* probes with vs without an unrelated update in between, measured only over stable stretches (neither this probe nor the previous one on the same options flipped) |
| **Staleness attribution** | share of violations whose licensing permission instance lies in $D_t$ — the memory entry supporting the action is exactly one the derivation layer deleted |
| **Canary rates** | false-violation and over-refusal rates on probes with no applicable constraint |
| **Cost** | tokens and latency |

All metrics are computed on the graph by the solver. No LLM judge is used anywhere.

## 7 Analysis (planned)

- **Which invalidations survive success-driven selection?** Cross-reference stale entries in experiential systems against their per-task success history.
- **Rules vs conclusions.** Compare systems that store conclusions ("A is banned") with systems that store rules plus priorities; the SUPPORT column isolates the difference.
- **Does more context help?** Long-context vs window vs notes, holding the backbone fixed.
- **Failure taxonomy.** Violations partitioned by whether the agent acted on a stale trap, an unmentioned distractor, an off-option entity, or abstained.

## 8 Limitations

- Constraint prose is template-generated. It is varied and self-contained, but it is not natural conversation. An LLM-assisted instantiation pass over the *same* event graph would raise surface realism without touching the ground truth; we leave it to future releases.
- Probes offer an explicit option set. This buys exact discriminativeness at the cost of some open-endedness: the agent chooses among named options rather than synthesising an action from scratch.
- Echo probes repeat a task at consecutive sessions to make adaptation lag observable, which is slightly unnatural as dialogue.
- SUPERSEDE and RETRACT are under-represented relative to CONFLICT and CONDITION because their motifs have fewer beats.
- Update interference is negative for memory-replaying policies whose failures are driven by their own history rather than by foreign updates; it should be read together with the arm sizes.
- Priorities are realised through three prose devices only. Real organisations resolve conflicts through many more, including implicit hierarchy; we trade that realism for check 7.
- The two worked examples and all seed domains are synthetic. The clinical domain in particular uses an invented formulary and must not be read as medical guidance.

## 9 Conclusion

REVOKE turns a question that memory research has treated as out of scope — *does what memory holds remain valid when the rules change?* — into a behavioural, programmatically graded benchmark. Its two-layer construction gives every action a unique verdict; its motif library and DAG traversal produce verified scenarios at scale; and its two grading gates close the exploits that a permissive default otherwise invites. The scripted `stale` policy already exhibits the pattern the benchmark exists to measure: XX% compliant success not because its skill degraded, but because the world moved and its memory did not.

## Appendix A · Worked examples (pinned as tests)

**A.1 Procurement: CONFLICT resolved by priority, flipped by SUPPORT.**
$f_1$: `low_budget` (fact). $r_1$: `ok(A) ⇐ ⊤` [π=1]. $r_2$: `¬ok(A) ⇐ low_budget` [π=2]. Defeat edge $n_2 \to n_1$; $E = \{n_{f_1}, n_2\}$, $D = \{n_1\}$, $C = \{\text{low\_budget}, \neg\text{ok}(A)\}$. `order(A)` violates; `order(B)` passes. SUPPORT raises $\pi(r_1)$ to 3: the edge reverses, $D = \{n_2\}$, $C = \{\text{low\_budget}, \text{ok}(A)\}$; `order(A)` is compliant again. No rule text changed.

**A.2 DevOps: SUPERSEDE, alternative derivations, no over-deletion.**
$r_1'$: `¬callable(v1)` [π=2] (SUPERSEDE of $r_1$). $r_2$: `callable(v2)` [π=1]. $r_3$: `deploy_ok ⇐ callable(X)` [π=1]. $r_3$ grounds to $n_{3a}$ (body never fires) and $n_{3b}$; $C = \{\text{callable}(v2), \neg\text{callable}(v1), \text{deploy\_ok}\}$. Incremental propagation over the old closure would delete `deploy_ok`; whole-set recomputation re-derives it through $n_{3b}$. `call(v1)` violates; `call(v2)` passes; `deploy_ok ∈ C` certifies the task remains compliantly completable.

## Appendix C · Agent system prompt

> You are an operations agent working with one team over many sessions. The team tells you how things work as you go: new rules, corrections to earlier rules, exceptions, and rulings that override earlier ones. Those messages are the only source of truth — your tools will not tell you the policy. When you are asked to carry out a task you must call the action tool exactly once with one of the options you were offered. You may call read-only tools first as much as you like; that is never penalised. What is penalised is acting in a way that contradicts the rules as they currently stand. Rules change: what was correct earlier in the conversation may be a violation now, and something that was forbidden earlier may be required now.
