REVOKE: Does an Agent's Experience Expire When the Rules Do?

A behavioural benchmark for procedural memory invalidation under rule evolution

Abstract

As LLM agents are deployed over long horizons, their memory systems have split into two families: declarative middleware that records facts about users and the world, and self-evolving experiential memory that distils insights, workflows and skills from the agent's own trajectories. Existing benchmarks probe the first family's recall fidelity and score answers; none asks what happens to either family when the rules of the world change. We present REVOKE, a benchmark in which agents execute open-ended tool-use tasks in a programmatically verifiable environment whose constraints evolve across sessions through six event types: addition, supersession, conditionalisation, conflict, support and partial retraction. Grading is behavioural and deliberately asymmetric: any action in the trace that contradicts the current constraint closure fails the episode, and everything else is unconstrained. Ground truth is a two-layer construction, a persistent base of defeasible rules with priorities and a per-step derivation layer computing the grounded extension of a defeat graph followed by a stratified closure, which gives unique, polynomial-time, deletion-order-independent grading with no LLM judge. Scenarios are generated by traversing a DAG of reusable event-subgraph motifs, so the constraint history is rich, verifiable, and produced at scale: n episodes in two difficulty tiers across five domains, with n graded decision points. We name the failure mode under test procedural memory invalidation: experience consolidated under an old world state becomes a violation-inducing rule after the state evolves, so that remembering more can mean violating more. Across n systems, we find headline finding.

1Introduction

Agent memory research advances along two largely disjoint tracks. The first treats memory as a declarative knowledge store: extract profiles, preferences and events from conversation, write them to external storage, retrieve on demand. Middleware such as mem0, MemOS and Zep belongs here, evaluated by long-horizon question answering in the style of LoCoMo and LongMemEval: did the system remember correctly? The second treats memory as procedural experience. ExpeL distils cross-task insights, Agent Workflow Memory induces reusable workflows, Voyager and SkillWeaver synthesise skills, and MemEvolve lets the memory architecture itself evolve. These systems are evaluated by task success on GAIA- and WebArena-style suites: did the agent get better at doing? Both tracks sidestep the same question. When the rules of the world change, does what memory holds remain valid?

For the declarative family the question has only just been raised. StateMemBench defines state tracking across sessions, where facts and decisions are revised and answers must reflect the current rather than a superseded state. This is an important step, but its grading operates at the answer level. Real agent failures occur at the level of behaviour: booking a vendor that has since been banned, calling an API that was deprecated, administering a drug that acquired a contraindication. A correct answer does not imply compliant behaviour, and behavioural grading naturally accommodates open-ended, multi-solution execution without a fixed answer space.

For the experiential family the question has never been examined. Procedural experience carries an implicit timestamp: every distilled insight and consolidated workflow was validated under some particular world state. When constraints evolve, that experience does not expire on its own. It continues to be retrieved and reused, and because it remains effective on the old distribution it can survive selection in success-driven evolution. We call this failure mode procedural memory invalidation. A system that only accumulates and never invalidates will exhibit the counterintuitive pattern of more experience, more violations.

REVOKE evaluates both families under one behavioural criterion. Our contributions:

  1. We formalise procedural memory invalidation and move evolving-state evaluation from the answer level to the behaviour level, grading traces rather than responses.
  2. We give a two-layer constraint construction, a grounded extension over a defeat graph followed by stratified Datalog closure, that guarantees unique, polynomial-time, deletion-order-independent grading and sidesteps the over-deletion pitfall of incremental view maintenance.
  3. We build the benchmark as a graph traversal: reusable event-subgraph motifs are composed by randomised topological linearisation into long, verifiable constraint histories, with ground truth always recomputed by the solver rather than taken from the template's intent. Two tiers separate memory-truncation failures from reasoning failures under noise and speaker hierarchy.
  4. We introduce metrics beyond pass/fail: per-event-type violation rate, adaptation lag, update interference and staleness attribution, all computable on the graph without annotation, and we report the first head-to-head comparison of declarative and experiential memory systems under this criterion.

2Formalisation: A Two-Layer Graph Construction

We represent constraint state as a graph, but split the intuitive picture, rules as nodes, relations as edges, contradiction as deletion, into two layers. Deletion happens only in a derivation layer recomputed at every timestep; the persistent layer never loses information on conflict. The split gives "delete the contradicted node" an exact semantics: it is precisely the iterated computation of the grounded extension of an argumentation framework in the sense of Dung (1995), unique, polynomial-time, and independent of deletion order.

2.1 Persistent layer

Ground truth at time t is a rule base R_t = {(r_i, π_i)} of defeasible rules with explicit integer priorities over a decidable Datalog fragment: heads are literals with classical negation, bodies are conjunctions of positive literals, variables are sorted. Six events drive evolution. ADD inserts a rule. SUPERSEDE replaces a rule's head or body. CONDITION rewrites a body between unconditional and conditional forms. CONFLICT inserts a rule with a contradictory head, resolved by priority rather than deletion. SUPPORT inserts nothing and increments the priority of its target, folding support into priorities and avoiding bipolar frameworks. RETRACT withdraws named ground instances of a rule. Except for SUPERSEDE and RETRACT the layer is append-only, which is what makes staleness attribution well defined.

2.2 Derivation layer

1 · GroundR_t → N_t
Instantiate every live rule over the sorted Herbrand universe. Nodes are ground instances, not rules, so a rule defeated in one context stays valid in another.
2 · Defeat graphn → m
An edge whenever two instances have complementary heads and π(n) > π(m). Priorities are strict, so the relation is acyclic.
3 · Grounded extensionE_t, D_t
Iterated deletion to fixpoint: a node is in once all its attackers are out, out once any attacker is in. Survivors E_t, deleted D_t.
4 · ClosureC_t
Stratified forward chaining over E_t alone. Recomputed over the whole surviving set, never propagated incrementally.

2.3 Grading and properties

An action a asserts a set of ground literals. It is a violation iff C_t ∪ assert(a) derives a contradiction, where the asserted literals are pushed through the surviving instances, so a violation can surface several derivation steps away from the action itself. Three properties hold throughout evolution. (i) E_t is unique and polynomial-time computable. (ii) Removing nodes or edges cannot create negative cycles, so every subgraph remains stratifiable; the semantics is well defined at every timestep. This is well-definedness, not conclusion preservation: negation makes the logic non-monotone and deletion can flip conclusions, which is exactly the phenomenon under test. (iii) The permissive default: if the closure says nothing about an entity, acting on it is not a violation.

2.4 Worked example

// procurement, after session 5 f1: low_budget. (fact, session 1) r1: ok(A) ⇐ ⊤ [π=1] (ADD, session 2: team lead's default vendor) r2: ¬ok(A) ⇐ low_budget [π=2] (CONFLICT, session 5: compliance) // derivation: edge n2 → n1; E = {f1, n2}, D = {n1}; C = {low_budget, ¬ok(A)} // order(A) asserts ok(A) → contradiction → violation. order(B): closure silent → pass. // session 9, SUPPORT: an executive directive endorses A, π(r1): 1 → 3. No rule text changes. // edge reverses n1 → n2; E = {f1, n1}, D = {n2}; C = {low_budget, ok(A)}. Ordering A is compliant again.

A single priority increment flips the entire extension. A memory system that froze the session-5 conclusion "A is banned" as a fact is now stale, while a system storing rules plus priorities adapts for free. The benchmark's engine reproduces this example and the deprecation example of the design note as executable tests.

3Benchmark Construction

3.1 The generator is a graph traversal

Constraint evolution is not hand-written per scenario. A motif is a small, domain-agnostic event subgraph over a permission predicate allow/1, a set of 0-ary context predicates, and a group predicate grp/2. Each motif emits an ordered chain of beats; a beat is one atomic step of evolution, optionally followed by a probe, a task the agent must perform at that moment. Chains are internally ordered and mutually independent, so the beats of all motifs in a scenario form a DAG whose linear extensions are the admissible timelines. The generator draws a randomised topological linearisation, weighting each chain by how many beats it has left, and lays the result onto a session grid with filler turns, distractor options and echo probes.

Ground truth is never taken from a motif's design intent. Once the timeline exists, every probe is re-scored against the closure the solver actually produces at that session. An interleaving that changes the intended semantics is therefore caught by the verifier rather than silently mislabelled. Every motif is designed so that the option set offered at consecutive probes stays constant while the compliant subset changes: an agent replaying experience from an earlier probe violates.

3.3 Domains and tiers

Five seed domains: platform API governance, procurement compliance, clinical medication constraints on a fully synthetic formulary, household automation preferences, and financial operation permissions. Each domain supplies 24 entities (36 in the hard tier), six context predicates, three groups, a mock tool surface with one graded act tool and read-only tools that deliberately return nothing substantive, and natural-language templates for every event type. The constraint history exists only in the conversation, which is what makes this a memory benchmark rather than a retrieval one.

The easy tier follows the design note's regimes: 10–18 or 22–40 sessions, sparse or dense events, all updates from a single team voice, obviously irrelevant filler. The hard tier adds five pressures, each of which keeps every verdict derivable from the transcript: (a) 60–140 sessions with several motifs in flight at once; (b) a declared speaker hierarchy in which a higher-ranked ruling beats a lower-ranked one regardless of order, so recency stops being a valid heuristic; (c) near-miss noise: proposals, hearsay, questions, cross-team anecdotes and stale "reminders" from speakers the hierarchy declares to have no authority, aimed at the current state (reminders that a banned entity is "the default", rumours that a licensed one is about to be blocked); (d) probes asked by unranked speakers who nudge towards a currently forbidden option; (e) terse phrasing and referential updates ("our ruling from session 16 is withdrawn") that require resolving a reference across the transcript.

3.4 Two grading gates

Violations are graded permissively, as the design note specifies. That alone is exploitable twice over: never act, or always act on something nobody ever mentioned. Both are violation-free and both are useless. An episode therefore scores 1 only if it is violation-free and every probe was completed, where completion requires acting on an option the closure positively licenses (allow(e) ∈ C_t).

Every probe offers 3–6 options mixing entities the transcript positively permits, entities it prohibits, and entities it never mentions (safe, but they do not complete the task), in shuffled order. The scripted refuse policy makes the point: it is violation-free and scores zero.

3.5 Solver-side acceptance

A scenario is emitted only if it passes seven checks, and failures are rejected rather than repaired: (1) the closure is convergent and consistent at every session; (2) no probe is must-violate, and every probe has at least one licensed option; (3) the over-deletion guard: a feasibility predicate with one derivation per permitted entity is present exactly when some permission survives; (4) at least one stale-memory trap, a probe where an option that was compliant last time is now a violation; (5) every probe is rendered into the transcript; (6) self-containedness: every violating option was named in an earlier turn, so its status is derivable; (7) recoverability: whenever a surviving instance defeats a deleted one, the transcript licenses that outcome by recency, by an explicit override, by the loser being marked advisory, or by the declared speaker hierarchy. 4Evaluation Protocol

An episode is replayed session by session. Update, noise and filler turns are delivered as messages; at a probe the agent must call the act tool with one of the offered options. Read tools are free and ungraded. The grader rebuilds ground truth from the item's event log with the same engine that generated it and never trusts cached labels. Only the blind view of an item is ever exposed to an agent: transcript text, tool surface and option sets, with turn kinds stripped so a scaffold cannot filter updates from noise by construction.

Memory conditions. full keeps the whole transcript in context (long-context upper bound); window-K shows only the last K sessions; notes-K adds a scratchpad the model maintains itself through a remember tool, the cheapest stand-in for declarative middleware; middleware conditions route the transcript through mem0, MemOS, Zep and OmniMemory; experiential conditions let ExpeL, AWM, Dynamic Cheatsheet and Voyager-style skill libraries consolidate across episodes of the same domain, unified through EvolveLab.

4.1 Metrics

CSR Compliant success rate: episodes that are violation-free and completed every probe. The headline.
VFR Violation-free rate: episodes with no violating action. Reported alongside CSR; alone it rewards inaction.
Violation rate by event type Probe-level, decomposed over the six events plus NOISE and CANARY probes.
Stale-trap rate Share of trap probes where the agent replayed the now-invalid choice.
Adaptation lag Probes after a state change until the agent stops violating; censored cases reported separately.
Update interference Violation-rate difference on unchanged probes with versus without an unrelated update in between, over stable stretches only.
Staleness attribution Share of violations whose supporting permission instance lies in the deleted set D_t.
Canary false-violation and over-refusal On probes with no applicable constraint.

All metrics are computed by the solver on the graph. No LLM judge appears anywhere in the pipeline.

6.4 Two observations from pilot runs

Two findings from small pilots are stable enough to state qualitatively and shape the protocol.

Difficulty on the easy tier comes from memory truncation, not from logic. On a 19-session episode with three traps, a frontier backbone with the full transcript in context passed every probe, and so did the same backbone with a self-maintained scratchpad, whose notes literally recorded which ruling outranked which. The same backbone restricted to the last three sessions made no violation either, but completed only k of 8 probes: unable to see the earlier approvals, it fell back to the one option nobody had ever mentioned. The completion gate is what makes that failure visible.

The elicitation harness is part of the measurement. When the test harness forced the agent to return, for every offered option, a status and the sessions that justify it, frontier backbones were error-free on the hard tier's first probes with and without their own scratchpad. That schema is a chain-of-thought scaffold most deployed agents never receive. The protocol therefore fixes a plain harness for all systems: the agent is asked only to act and to say in a sentence what it did.

7Related Work

Long-horizon memory benchmarks. LoCoMo and LongMemEval measure recall over long conversations with answer-level scoring; StateMemBench adds revised state across sessions, still QA-shaped. REVOKE keeps the multi-session setting and moves the criterion to behaviour.

Memory systems. Declarative middleware (mem0, MemOS, Zep, OmniMemory) and self-evolving experiential memory (ExpeL, Agent Workflow Memory, Voyager, SkillWeaver, Dynamic Cheatsheet, MemEvolve), unified for comparison in EvolveLab. To our knowledge no prior work quantifies invalidation of consolidated experience.

Defeasible reasoning and argumentation. The grounded extension is Dung's (1995); our two-layer construction instantiates it over ground rule instances with strict priorities and composes it with stratified Datalog. Delete-and-Rederive and related view-maintenance algorithms motivate the recomputation choice.

Agent safety and constraint following. Rule-following and tool-use safety suites grade compliance against static rule sets; REVOKE grades against a rule set that evolves under the agent, which is where memory enters.

8Limitations

  • Constraint prose is template-generated. It is varied, self-contained and, in the hard tier, deliberately noisy, but it is not natural conversation; an LLM-assisted instantiation pass over the same event graph would raise surface realism without touching the ground truth.
  • Probes offer an explicit option set, buying exact discriminativeness at the cost of some open-endedness.
  • Echo probes repeat a task at consecutive sessions to make adaptation lag observable, which is slightly unnatural as dialogue.
  • SUPERSEDE and RETRACT are under-represented relative to CONFLICT and CONDITION in the easy tier because their motifs have fewer beats.
  • Update interference is negative for policies that replay their own history, whose failures are self-inflicted rather than induced by foreign updates; the metric is read with its two arms.
  • Probe-level facts (a task's own properties such as an amount or a traffic origin) are not yet modelled; contexts are global toggles. Turn-level ordering inside a session is not modelled either: updates render before probes in the same session.

9Conclusion

REVOKE asks a question neither memory family has been tested on: when the rules change, does what memory holds remain valid, and does the agent's behaviour show it? By grading traces against a constraint closure that is recomputed at every step, and by generating long, verifiable constraint histories as traversals of an event-subgraph DAG, the benchmark isolates memory consistency from policy optimality and puts a number on procedural memory invalidation. Closing sentence on the headline result.
